# 2026-10-16 회의록 HTML 내보내기와 포함 옵션 기본값

- 요청: 공유·다운로드 창의 포함 옵션을 기본 체크로, 다운로드 형식에 HTML 추가.
- 기본값: 공유 창의 섹션 기본에 논의·미해결을 더했다(요약·결정·할 일·논의·미해결). 다운로드 창은 이미 전 섹션 선택이다. 아래는 일부러 껐던 값이라 그대로 둔다.
  - 참석자·화자 이름·담당자 포함(`include_people`): 백엔드 계약 기본 false. 구조적 이름 필드를 기본 제외하는 개인정보 최소화 설계(ADR 0030, 공개 계약서 §include_people).
  - 근거 발화 포함(`include_evidence`): 기본 false이고 전사 섹션이 있어야만 켤 수 있다.
  - 공유 창의 전사: 공개 링크로 원문 발화가 나가고 본문 속 이름은 자동 익명화되지 않는다(계약서 §14 근처 설명). 전사를 켜야 근거 발화도 켤 수 있다.
  - 회사 자료 확인 체크박스: 기본값이 아니라 외부 전달 확인 절차다. 테스트로 미체크를 고정했다.
- HTML 형식: 서버 형식 목록(txt/md/json/csv)은 건드리지 않고 브라우저에서 만든다. 검토한 미리보기 문서(포함 옵션이 이미 적용된 공개용 DTO)를 `meetingHtml.template.html`의 `<script type="application/json">`에 넣고, 같은 파일의 스크립트가 textContent로만 그린다.
- 디자인 재사용: 공유 페이지가 쓰는 tokens/typography/prose/meetings/sharing CSS 원문을 `?raw`로 인라인한다(HTML 저장 때만 불러오는 별도 청크). 발화 묶음은 `documentTurns.ts`로 화면과 공유한다.
- 보안: JSON의 `<`, `>`, `&`, U+2028/9를 `\uXXXX`로 치환, 한 번의 치환으로 자리표시자 재치환 방지, 파일에 `default-src 'none'` CSP 메타. HTML 문자열을 해석하는 DOM API 미사용을 테스트로 고정.
- 공개 페이지: 게시자가 다운로드를 하나라도 허용한 경우에만 HTML 사본을 같이 보여 준다. 조회 전용이면 도구가 없다. 이는 서버가 HTML을 모르기 때문에 생긴 클라이언트 쪽 규칙이다.
- 테스트 설정: HTML 내보내기가 CSS 원문을 인라인하므로 vitest의 `css.include`에 `?raw`를 추가했다.
