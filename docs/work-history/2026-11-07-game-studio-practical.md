# 게임 스튜디오 제작 여정 1차 구현

기준 e2d89e6. 사용자 승인에 따라 연구의 기존 게임 진입·실패 복구·요청 문맥·후보 검토를 실제 컴포넌트에 적용했다.

- 내 게임 목록을 먼저 보여주고 새 게임 만들기·기존 게임 연결을 별도로 연다. 연결 진단 결과의 경고를 보존하고 실제 연결 후 해당 게임으로 이동한다.
- 성공 빌드 없이 글로 개발·수리를 요청한다. 화면 증거는 기준 빌드가 없으면 거부하고, 업로드 실패·서버 거부 때 입력을 보존한다. 진행 중 작업이나 상태 조회 오류에서는 다음 제출을 막는다.
- 장면·챕터와 확인할 결과를 요청 본문에 함께 보낸다. 작업 목록에는 사용자 요청 요약과 코드 작업 완료를 표시한다.
- 상태에 따라 지금 할 일과 주 행동을 보여준다. 플레이 불가 때 빈 게임 화면을 줄이고 조작할 수 없는 도구 모음을 숨긴다.
- 스튜디오 요청은 review_before_apply=true로 보낸다. 기존 플레이 버전을 유지한 새 후보를 해 본 뒤 이 버전 사용하기로 선택한다. 이전 버전 복원 경로는 보존한다.

검증: 게임 관련 Vitest 136 passed, tsc -b 통과. 후보 기능 이전 프로덕션 번들 빌드 통과(후보 변경 이후 최종 빌드는 이어서 실행). 실제 컴포넌트+합성 API로 390x844 실패 상태에서 수리·장면·확인 결과 제출 후 AI 작업 목록에 같은 요청이 보이는 것을 승인 브라우저로 확인했다. 콘솔 오류 0. 기존 게임 연결·준비/미준비 후보 안내와 1440x900 화면도 확인했다. 운영 API·게임·에이전트 실행을 대신한 검증은 아니다.

프리뷰: scripts/game-studio-preview/serve.mjs는 polling watcher와 5분 자동 종료를 사용한다. 백엔드 새 API 배포 전에 프론트 main을 게시하면 추가 요청 필드가 거부될 수 있으므로 백엔드 적용을 먼저 확인한다.
